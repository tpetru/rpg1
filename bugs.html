#001

Newspaper edit — text tăiat, nu se face wrap pe rândul următor

Medium Deschis

La editarea ziarului (newspaper edit), textul nu este împărțit pe rândul următor atunci când depășește lățimea, așa că se afișează doar un număr limitat de caractere — restul textului este tăiat.

De implementat un split / word-wrap care rupe textul pe rândul următor la depășirea numărului maxim de caractere per linie, în loc să trunchieze.

📅 Raportat: 2026-07-08 · 📍 Sistem: Newspaper

#002

Toate comenzile se comportau ca /stats

High Rezolvat

Orice comandă tastată producea output-ul comenzii /stats. Cauza: numele comenzii fusese șters accidental din guard, rămânând if(strcmp(cmd, "", true) == 0). strcmp din plugin-ul de string returnează 0 (match) la comparația cu string gol, deci blocul prindea orice comandă — și fiind aproape de începutul dispecerului, deturna tot lanțul.

Fix: restaurat if(strcmp(cmd, "/stats", true) == 0). Aceeași cauză a produs și bug-ul /farm buy fără argument (cumpăra tractor implicit, pentru că strcmp("", "tractor") dădea match) — rezolvat cu un guard if(!strlen(type)) return -1; în Farm_ModelFromType.

📅 Rezolvat: 2026-07-14 · 📍 Sistem: OnPlayerCommandText

#003

Stack overflow — utilizare stack peste limita alocată

High Rezolvat

Gamemode-ul nu avea #pragma dynamic, deci stack/heap-ul era la default 4096 celule, în timp ce utilizarea maximă estimată era 4627 celule — depășire garantată, cu coliziune stack/heap și corupere de memorie la runtime.

Fix: adăugat #pragma dynamic 32768. Verificat în header-ul .amx: stack/heap = 32768 celule. De reverificat dacă gamemode-ul mai crește semnificativ.

📅 Rezolvat: 2026-07-14 · 📍 Sistem: Compilare / runtime

#004

/changeskin — „nu e setat skin pentru rangul tău", deși erau setate în DB

Medium Rezolvat

Uniformele de facțiune erau corect în DB (factions.skin1/skin2/skin3), dar Faction_SkinForRank returna mereu 0. Cauza: SELECT-ul din Factions_Load lista coloanele explicit și omitea skin1/skin2/skin3, deci cache_get_value_name_int nu găsea nimic și valorile rămâneau 0 în memorie.

Fix: adăugate skin1, skin2, skin3 în SELECT. Lecție: când adaugi o coloană nouă la un tabel, verifică și query-ul de load — dacă listează coloanele explicit, trebuie actualizat.

📅 Rezolvat: 2026-07-14 · 📍 Sistem: Skinuri / Facțiuni

#005

/event race random — numele mașinii nu corespundea

Low Rezolvat

#008

Map icon slots pizza/burger se pot suprapune

Low Deschis

PIZZA_ICON_SLOT_BASE = 90 și BURGER_ICON_SLOT_BASE = 95 au fost alese când MAX_FOOD_LOCATIONS era 5. Acum e 20, deci pizza ar folosi sloturile 90-109 și burger 95-114 — se suprapun, iar SetPlayerMapIcon acceptă doar sloturile 0-99.

Nu se manifestă cât timp sunt puține locații per tip (≤5). Fix corect: migrarea pizza/burger la map icon-uri dinamice (streamer), cum s-a făcut deja la Cluckin Bell (g_MealIcon).

📅 Raportat: 2026-07-14 · 📍 Sistem: Fast-food / Map icons
